# Compression and distillation experiments on CIFAR-10

## 1. Abstract

This report compares three model-efficiency techniques on CIFAR-10: global unstructured magnitude pruning with fine-tuning, dynamic quantization of linear layers, and response-based knowledge distillation from a ResNet-18 teacher into a MobileNetV3-Small student. A baseline ResNet-18 reaches 93.11% test accuracy. Pruning at 90% sparsity retains 92.59% after fine-tuning, a drop of only 0.52 percentage points. Knowledge distillation into MobileNetV3-S small achieves 76.52% versus 76.00% from scratch, a modest 0.52-point gain. Dynamic quantization of Linear layers preserves accuracy (93.09%) but does not reduce size or latency on this conv-heavy architecture, confirming that dynamic Linear-only quant is the wrong tool for convolutional models. All experiments ran on a single Kaggle Tesla T4 GPU.

## 2. Motivation

Production ML rarely optimizes accuracy alone. Edge devices, batch cost, and p95 latency force tradeoffs among quality, size, and speed. Portfolio work that only trains a large classifier misses that reality. Compression and distillation are standard tools for ML engineers working on model optimization: pruning removes weights, quantization reduces numeric precision, and distillation transfers behavior into a smaller architecture. This project treats those methods as experimental systems with honest measurement, including weak or negative results.

## 3. Methods

### 3.1 Baseline

Teacher and pruning substrate: ResNet-18 adapted for CIFAR-10. The ImageNet stem is replaced with a 3x3 stride-1 convolution and the max-pool is removed so 32x32 inputs retain spatial resolution. Training uses SGD (lr 0.1, momentum 0.9, weight decay 5e-4), MultiStepLR at epochs 30 and 40 (gamma 0.1), 50 epochs, standard CIFAR augmentation (random crop + horizontal flip) and CIFAR-10 normalization.

### 3.2 Global magnitude pruning

We apply `torch.nn.utils.prune.global_unstructured` with L1 unstructured pruning over all `Conv2d` and `Linear` weights at amounts 0.5, 0.8, and 0.9. Masks remain during fine-tuning so zeroed weights stay zero. After fine-tuning we call `prune.remove` to bake masks into tensors for serialization and benchmarking. Fine-tune schedule: 20 epochs, lr 0.01, milestones at 10 and 15.

### 3.3 Dynamic quantization

We apply dynamic quantization (`qint8`) to `nn.Linear` modules only and evaluate on CPU. CIFAR ResNet-18 is convolution-heavy, so size and latency wins may be modest. That outcome is still informative: it shows when a technique is the wrong tool for a given architecture.

### 3.4 Knowledge distillation

Student: MobileNetV3-Small with a 10-way classifier head. Loss:

\[
\mathcal{L} = \alpha\,\mathrm{CE}(z_s, y) + (1-\alpha)\,T^{2}\,\mathrm{KL}\big(\log\mathrm{softmax}(z_s/T),\,\mathrm{softmax}(z_t/T)\big)
\]

Defaults: \(T=4\), \(\alpha=0.3\), 50 epochs, lr 0.05, milestones 30/40. Teacher is frozen in eval mode. We also train a **scratch control** (same student architecture and schedule, no teacher) to isolate the distillation signal.

## 6. Discussion

### 6.1 Accuracy under a fixed size budget

The student models (MobileNetV3-Small at 5.96 MB) are 7.2x smaller than the ResNet-18 baseline (42.70 MB) but pay a 16.6-point accuracy cost (93.11% vs 76.52%). Pruning achieves a better accuracy/size tradeoff within the ResNet architecture: 90% sparsity reduces nonzero parameters to 1.13M (fewer than the student's 1.53M) while retaining 92.59% accuracy, a 15.9-point advantage over the student at comparable parameter count. However, unstructured pruning does not reduce the serialized size because zeros are still stored as float32 values.

### 6.2 Pruning sparsity vs accuracy

Fine-tuning after global L1 pruning recovers accuracy remarkably well:

| Sparsity | Accuracy | Delta from baseline |
| --- | --- | --- |
| 0% (baseline) | 93.11% | 0.00 |
| 50% | 93.08% | -0.03 |
| 80% | 92.91% | -0.20 |
| 90% | 92.59% | -0.52 |

The accuracy degradation is nearly linear and very gentle. Even at 90% sparsity (removing 9 out of 10 weights), the model loses only 0.52 percentage points. This is consistent with the lottery ticket hypothesis: most weights in a trained ResNet-18 are redundant, and a small subnetwork suffices. No accuracy cliff was observed within the tested range. The practical implication is that unstructured magnitude pruning is highly effective for reducing parameter count, though the dense storage format means disk size does not shrink.

### 6.3 Distillation vs scratch control

The distilled MobileNetV3-Small student reaches 76.52% versus 76.00% for the scratch control, a 0.52-point gain from the teacher signal. Both used identical schedules (50 epochs, lr 0.05, milestones 30/40). The gain is modest but consistent: the soft targets from the ResNet-18 teacher provided a slight regularization benefit. This suggests the teacher's dark-label information (inter-class similarities) helps the student generalize marginally better, but the effect is small on CIFAR-10 with this student architecture. A stronger student (e.g. MobileNetV2) or a more aggressive temperature schedule might amplify the gap.

### 6.4 Dynamic quantization on a conv-heavy model

Dynamic quantization of `nn.Linear` layers to `qint8` (fbgemm engine) preserved accuracy almost perfectly: 93.09% vs 93.11% for the FP32 baseline, a 0.02-point drop. However, the technique is a poor fit for this architecture:

- **Size**: 42.69 MB vs 42.70 MB, a 0.04% reduction. ResNet-18 is convolution-heavy; Linear layers are a tiny fraction of parameters, so quantizing only them barely moves the needle.
- **Latency**: 17.88 ms on CPU vs 2.49 ms on GPU. The quantized CPU latency is 7.2x slower than the FP32 GPU latency (device difference, not a quantization issue). On the same CPU, dynamic quant can help Linear-heavy models (transformers, MLPs), but not conv-heavy CNNs.

This is a valid negative result: it demonstrates that dynamic quantization is architecture-dependent and should be paired with static quantization or QAT for convolutional models.

### 6.5 Latency honesty

PyTorch eager unstructured sparsity does not yield automatic wall-clock speedups without sparse kernels. The pruned models show identical latency to the baseline (2.49-2.53 ms) despite having 50-90% zero weights, because dense kernels still execute on the full parameter tensors. Real speedups would require structured pruning (channel/filter removal), sparse tensor kernels, or export to ONNX/TensorRT with sparsity-aware runtimes. The student model (MobileNetV3-Small) is slower than the ResNet-18 baseline on GPU (4.87 vs 2.49 ms) despite being smaller, likely due to depthwise convolutions being less GPU-efficient than standard convolutions on the T4.

## 7. Limitations and next steps

- Unstructured pruning reduces parameter count but not storage size or latency without sparse kernels.
- Dynamic quant only hits Linear layers; static PTQ / QAT would better target convolutions.
- CIFAR-10 only; ImageNet-scale or detection/segmentation would stress transfer.
- No ONNX Runtime, TensorRT, or mobile delegate measurements in v1.
- Distillation gain is modest (0.52 points); a stronger student or different hyperparameters might widen the gap.
- Next steps: structured channel pruning, QAT, export + ORT benchmarks, stronger students, multi-seed error bars.

## 8. CV bullet

Trained a CIFAR-10 ResNet-18 baseline (93.11% accuracy) and compared global magnitude pruning at 50/80/90% sparsity (92.59-93.08%), response-based knowledge distillation into MobileNetV3-Small vs scratch control (76.52% vs 76.00%), and dynamic qint8 quantization (93.09%) on accuracy, parameter sparsity, model size, and inference latency; ran all experiments on a Kaggle Tesla T4 GPU and documented tradeoffs including the negative result that dynamic Linear-only quantization does not benefit conv-heavy architectures.
